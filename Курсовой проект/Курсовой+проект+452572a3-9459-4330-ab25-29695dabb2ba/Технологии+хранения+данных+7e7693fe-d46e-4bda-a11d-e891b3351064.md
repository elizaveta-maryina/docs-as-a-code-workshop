# Определение хранимых сущностей

## Заказ

|||
|-|-|
|Описание|Хранит информацию о заказе, полученном из канала продаж и обрабатываемом в системе по внутренней модели статусов.|
|Атрибуты сущности|`id` — уникальный идентификатор заказа в системе.
`number` — номер заказа для отображения пользователям.
`createdAt` — дата/время создания заказа в системе.
`updatedAt` — дата/время последнего изменения данных заказа.
`channelId` — ссылка на канал продаж, из которого получен заказ.
`customerId` — ссылка на клиента, оформившего заказ.
`totalAmount` — итоговая сумма заказа.
`currency` — валюта суммы заказа.
`fulfillmentMethod` — способ получения (доставка/самовывоз).
`deliveryAddress` — адрес доставки (если выбран способ “доставка”).
`currentStatus` — текущий статус заказа по внутренней модели системы.
`statusSource` — источник последнего изменения статуса (канал/система).
`statusChangedAt` — дата/время последнего изменения статуса.
`hasSyncIssue` — признак наличия ошибки синхронизации по заказу.
`hasStatusConflict` — признак конфликта статусов/недопустимого перехода.
`needsAttention` — признак, что заказ требует внимания (конфликт или ошибка).|
|Кто взаимодействует|Менеджер (просмотр списка заказа/карточки заказов), система (обновляет статус), админ (контроль процесса обработки заказа).|
|Характер взаимодействия |Транзакционные (операционные).|

## Клиент

|||
|-|-|
|Описание|Хранит данные покупателя, связанные с заказом.|
|Атрибуты сущности|`id` — уникальный идентификатор клиента в системе.
`fullName` — имя/ФИО клиента.
`phone` — телефон клиента (опционально).
`email` — электронная почта клиента (опционально).|
|Кто взаимодействует|Менеджер (просмотр), система (создание/обновление при импорте заказов).|
|Характер взаимодействия |Транзакционные.|

## Канал продаж

|||
|-|-|
|Описание|Хранит подключение к внешнему источнику заказов (маркетплейс/сайт) и его состояние в системе.|
|Атрибуты сущности|`id` — уникальный идентификатор подключения канала.
`name` — название канала.
`type` — тип канала (например, маркетплейс/сайт).
`enabled` — признак, что канал включен для синхронизации.
`state` — агрегированное состояние канала (включён/выключен/ошибка).
`config` — параметры подключения к каналу:
              `apiKey` — ключ доступа (если используется).
              `token` — токен доступа (если используется).
              `url` — базовый URL API (если требуется).
`lastSyncAt` — дата/время последней синхронизации по каналу.
`lastSyncResult` — результат последней синхронизации (успех/ошибка).
`lastError` — информация о последней ошибке:
              `code` — код ошибки.
              `message` — текстовое описание ошибки.
              `occurredAt` — дата/время возникновения ошибки.|
|Кто взаимодействует|Администратор (управляет каналами), система (использует при синхронизации и обновляет lastSync/ошибки).|
|Характер взаимодействия |Транзакционные (управленческие настройки)|

## История изменения статусов

|||
|-|-|
|Описание|Хранит историю изменения статусов заказа для прозрачности процесса и отслеживания ошибок.|
|Атрибуты сущности|`id` — идентификатор записи.
`orderId` — ссылка на заказ.
`changedAt` — время изменения.
`status` — установленный статус.
`source` — источник изменения (канал/система).
`comment` — комментарий (опционально).
`actor` — кто инициировал изменение (`type`, `name`).|
|Кто взаимодействует|Менеджер (просмотр), система (запись при изменении статуса).|
|Характер взаимодействия |Транзакционные, событийные (append-only).|

## Маппинг статусов

|||
|-|-|
|Описание|Хранит соответствие статусов конкретного канала внутренним статусам системы, используемое при синхронизации.|
|Атрибуты сущности|`id` — идентификатор правила.
`channelId` — ссылка на канал.
`channelStatusCode` — статус, приходящий из канала.
`internalStatus` — внутренний статус системы.
`isActive` — признак активности правила.
`updatedAt` — время последнего изменения.
`note` — пояснение (опционально).|
|Кто взаимодействует|Администратор (настраивает), система (использует).|
|Характер взаимодействия |конфигурационные/справочные.|

## Журнал синхронизации

|||
|-|-|
|Описание|Хранит информацию о запусках синхронизации, ошибках и результатах.|
|Атрибуты сущности|`id` — идентификатор сессии синхронизации.
`channelId` — ссылка на канал, по которому выполнялась синхронизация.
`startedAt` — дата/время начала синхронизации.
`finishedAt` — дата/время завершения синхронизации.
`result` — итог выполнения синхронизации (успех/ошибка).
`processedCount` — количество обработанных обновлений статуса.
`successCount` — количество успешных обновлений.
`errorCount` — количество ошибок/конфликтов.
`errors` — список ошибок (опционально):
              `code` — код ошибки.
              `message` — описание ошибки.
              `orderId` — ссылка на заказ, если ошибка относится к конкретному заказу (опционально).|
|Кто взаимодействует|Администратор (анализ), система (запись).|
|Характер взаимодействия |операционные события/аудит (append-only).|

|**Итоговое решение**|**Реляционная БД (OLTP)**|**Реляционная БД (OLTP)**|**Реляционная БД (OLTP)**|**Реляционная БД (OLTP)** (append-only таблица)|**Реляционная БД (OLTP)** (справочник/конфигурация)|**Реляционная БД (OLTP)** в MVP; при росте возможно вынести в лог/событийное хранилище|

В MVP целесообразно использовать один контур хранения (реляционная БД (OLTP)) для всех сущностей, т.к. данные структурированы, есть связи между сущностями, требуются транзакции и сложные выборки (фильтры/сортировка) для экрана реестра заказов. Для сущностей событийного характера (история статусов, журнал синхронизации) используются append-only таблицы и индексация по ключам (orderId, channelId, время). При росте нагрузки журнал синхронизации может быть вынесен в отдельное лог/событийное хранилище без изменения бизнес-модели.
